El change construye la pantalla única de composición en apps/web: un formulario React Hook Form con chips para Para/CC/CCO, asunto de una línea y cuerpo React Quill (negrita, cursiva, listas), en español e identidad NTT DATA. Cubre HU-05, HU-06, HU-07, HU-09 y HU-10. Sin validación, sin envío ni adjunto (fronteras a fases 5/4/6).

#Supuestos y huecos

  • Supuesto: el estado es local a la pantalla con React Hook Form; no hay store global (arquitectura §8).
  • Supuesto: el botón Enviar se renderiza pero es inerte en esta fase; el envío real (useSendEmail) llega en la fase 4.
  • Hueco: no hay validación de formato ni obligatorios (HU-08/HU-14, fase 5); los chips se aceptan sin validar.
  • Hueco: el cuerpo HTML no se sanea en cliente (el saneamiento es del backend, HU-17, fase 7).

#Casos de uso

El usuario compone el correo en una sola pantalla: gestiona destinatarios como chips, escribe el asunto y redacta el cuerpo con formato acotado.

#Actividad

Flujo de introducción de una dirección como chip en un campo de destinatarios, con la baja de un chip existente. Sin validación de formato en esta fase.

#Secuencia 1 - Añadir destinatario como chip

El usuario teclea una dirección y confirma con Enter o coma; el campo la convierte en chip y actualiza el array del formulario.

#Secuencia 2 - Redactar cuerpo con formato

El usuario aplica negrita, cursiva o listas en el editor; React Quill produce HTML que se guarda en el campo del formulario.

#Estado

Ciclo de un campo de chips: del campo vacío a tener chips, pasando por la edición del input.

Change ui-envio-feedback · Generado el 2026-07-11

El change cablea el envío desde la UI: al pulsar Enviar, useSendEmail llama a apiClient (JSON a POST /api/send), deshabilita el botón durante el envío y muestra un FeedbackBanner de éxito o error; al éxito limpia el formulario y al error conserva los datos. Cubre HU-15 y HU-16 y cierra el hito MVP F1. Sin validación, sin adjunto ni saneamiento (fases 5/6/7).

#Supuestos y huecos

  • Supuesto: la llamada es cross-origin directa a VITE_API_BASE_URL (default localhost 3000); la api ya habilita CORS para WEB_ORIGIN.
  • Supuesto: el payload es JSON (sin adjunto); la migración a FormData es la fase 6.
  • Hueco: no hay validación de cliente en esta fase (HU-08/HU-14, fase 5); el envío se dispara con lo que haya en el formulario.
  • Hueco: el saneamiento del cuerpo es del backend (HU-17, fase 7).

#Casos de uso

El usuario envía el correo compuesto y recibe feedback del resultado; el sistema evita envíos duplicados mientras el envío está en curso.

#Actividad

Flujo de envío directo con las ramas de éxito y error, incluida la prevención de envíos duplicados por deshabilitado del botón.

#Secuencia 1 - Envío con éxito

El usuario envía; el hook deshabilita el botón, el cliente entrega el correo y, con la respuesta correcta, se muestra éxito y se limpia el formulario.

#Secuencia 2 - Error de envío o red

Si el backend responde error o falla la conexión, el cliente devuelve un resultado de error que se traduce a un mensaje en español; el formulario conserva los datos.
